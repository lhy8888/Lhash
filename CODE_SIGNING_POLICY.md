# Code Signing Policy

This document defines how LHash release builds may be code-signed.

## Scope

This policy applies to the official public release artifacts published from:

- the GitHub repository: <https://github.com/lhy8888/Lhash>
- the GitHub Releases page for this repository

## Signing purpose

Code signing is used only to:

- establish publisher identity for official release artifacts
- protect users against tampered or substituted binaries
- improve Windows trust validation for official public releases

Code signing is **not** used to imply that unsigned builds, local developer builds, forks, or unofficial mirrors are official LHash releases.

## Allowed artifacts

Only official release artifacts produced from this repository may be signed, including:

- the shipped native Windows desktop executable `LHash.exe`
- official release packages generated by the release workflow

Preview, test, local, private, or manually modified artifacts must not be presented as official signed releases.

## Approval responsibility

The signing approval boundary for LHash is:

- repository owner and release maintainer: <https://github.com/lhy8888>

Changes included in a signed release must come from the maintained repository branch and release process controlled by the repository owner or explicitly approved maintainers.

## Source of truth

The GitHub repository history and tagged releases are the source of truth for what may be signed.

Artifacts must correspond to:

- a reviewed repository state
- a release workflow run
- an official release tag when the artifact is intended for public distribution

## Unsigned builds

Unsigned builds may exist for testing, CI validation, or preview distribution.

Unsigned builds:

- are not equivalent to officially signed public releases
- may still show `Publisher unknown`
- should not be treated as trusted public release artifacts solely because they were built from the repository

## Revocation and response

If a signing path, signing credential, or signed artifact is believed to be compromised, LHash maintainers may:

- stop publishing signed releases
- revoke or rotate the signing configuration
- remove affected release assets
- publish replacement artifacts and security guidance

## Public transparency

LHash publishes its code-signing approach in:

- [Code signing guide](CODE_SIGNING.md)
- this policy document

These documents exist so that users and signing providers can verify how release signing is intended to work.
